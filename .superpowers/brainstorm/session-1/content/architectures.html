Đề xuất Kiến trúc Hệ thống

Hãy xem qua các phương án kiến trúc bên dưới. Phương án A là phương án khuyên dùng cho dự án này.

A

Next.js Monolith (Khuyên dùng)

Tất cả chức năng (Admin, Nhà giặt, Form QR Khoa phòng) tích hợp chung trong một ứng dụng Next.js. Kết nối trực tiếp PostgreSQL qua Prisma.

B

Phân tách Frontend và API Backend

Next.js đảm nhiệm Frontend riêng biệt. Một dự án API Backend độc lập (Node.js/Express hoặc NestJS) kết nối database để xử lý nghiệp vụ.

Phương án A: Next.js Monolith

Đặc điểm:

Sử dụng Next.js App Router làm cả giao diện (React) lẫn API Routes để xử lý nghiệp vụ backend. Xác thực yêu cầu QR bằng mã thông báo bảo mật (Signed Token) trong URL.

Ưu điểm

  • Triển khai cực nhanh, dễ bảo trì (1 codebase duy nhất).
  • Prisma kết nối trực tiếp giúp truy vấn database siêu nhanh.
  • Tối ưu hóa SEO và bảo mật dễ dàng qua Server Components.

Nhược điểm

  • Khó tách riêng đội ngũ làm Front-end và Back-end nếu dự án phình to.
Phương án B: Split Frontend/Backend

Đặc điểm:

Ứng dụng Next.js chỉ gọi API qua HTTP. API Server riêng chạy Express/NestJS xử lý toàn bộ Prisma và PostgreSQL.

Ưu điểm

  • Kiến trúc phân tách rõ ràng.
  • Dễ dàng mở rộng API phục vụ cho các hệ thống khác của bệnh viện (HIS/LIS) sau này.

Nhược điểm

  • Tăng gấp đôi công sức cài đặt, cấu hình, và triển khai (2 server độc lập).
  • Phải xử lý vấn đề CORS, phân quyền phức tạp hơn giữa 2 môi trường.
